## Proven source-level orientation defect

1. `src/pipeline/RemeshPipeline.cpp`, `orient_quads_to_source_normals` (~10949–11033): treats each quad separately. It computes the normal as `(B-A) × (C-A)` using **only the first three corners**, and swaps corners 1 and 3 if it disagrees with a selected source normal. This does not preserve relative orientation on shared interior edges. The function accepts but ignores `quadLineage`, uses a common face only when all four corner provenance records name the identical source-face row, and otherwise queries an unrestricted centroid projection. Projection is not the same as authoritative compatible source-chart provenance, especially for close sheets.
2. This three-corner normal is not a valid general substitute for whole-quad signed orientation. Exact planar counterexample with ordered corners `A=(0,0)`, `B=(1,0)`, `C=(2,-1)`, `D=(0,10)` and +Z source normal: the polygon is simple, full signed double-area is **+19**, but the first-triangle signed cross is **−1**. The helper reverses it to `(A,D,C,B)`, changing full signed double-area to **−19**. This demonstrates a **possible incorrect flip** without invoking the production binary. It does not prove these four points occur in Vase; the example is an algebraic falsifier of the helper's claimed general orientation predicate.
3. `src/geometry/PureQuadCompletion.cpp`, `quad_embedding_failure` (~500–579), already computes a complete Newell polygon normal and compares it to source orientation (60-degree agreement threshold), rather than using the first triangle. Therefore completion and the later pipeline normal-repair step use **inconsistent geometric predicates**.
4. `src/geometry/PureQuadCompletion.cpp`, `stitch_pure_quad_patches` (~3744–3950): publishes the completed-face corner cycles as-is. Its initial `edge_incidence` gate checks only unoriented edge multiplicities 1 or 2; it has no directed opposite-twin check. It validates Euler, vertex-fan connectivity, component and boundary loops, but these checks can all pass with same-direction shared-edge traversal. This is an **upstream diagnostic gap**. The absence of a guard does not prove the assembler is the original Vase orientation producer.
5. `src/pipeline/RemeshPipeline.cpp` (~14407–14473, 14847, 15008–15040): converts stitched quads to `completedQuads`, runs the independent per-face normal helper, then invokes `validate_source_authoritative_final_surface_mesh` **before optimization**. When this returns unaccepted it attributes failure to `completion/output-validation` and exits before the optimizer. It is a pre-optimization validation boundary, not proof that the completion topology producer itself is responsible for the failing predicate.

## Additional validator defect: the failure label is winding-dependent

`include/directional/validation/MeshValidator.h`, `quad_self_intersects` (~307–325), selects a projection axis from the first triangle `(p1-p0)×(p2-p0)` before checking opposite-edge crossings. Reversing the same cycle (`0,1,2,3` → `0,3,2,1`) can change that chosen axis. Therefore a `SelfIntersectingFace` issue may change even when all physical corner positions and undirected edges are unchanged. This is a **source-proven diagnostic instability**, distinct from the actual geometric shape and from the orientation helper's wrong-normal defect.

Independent integer-arithmetic witness: `A=(0,0,0)`, `B=(3,1,0)`, `C=(2,2,1)`, `D=(-4,-3,-3)`. The forward `(A,B,C,D)` first-triangle normal is `(1,-3,4)`, so the validator projects to XY (drop Z) and reports **no strict opposite-edge crossing**. Reversal `(A,D,C,B)` has first-triangle normal `(3,-2,-2)`, so it projects to YZ (drop X) and reports **a strict crossing**. The four points and undirected polygon edges are identical. This is a deterministic counterexample to orientation-invariance of that *validator*, not evidence that Vase has these coordinates or that its geometric embedding is valid. A projection-independent source-chart/bilinear or true 3D edge/face oracle is required before interpreting the post-orientation intersection count.

For the **actual source-authoritative output-validation path**, `SourceAuthoritativeMeshValidator.cpp` (~1040–1057) calls `MeshValidator::validate_surface_mesh` with `topologyOnly=true` and `requireConsistentOrientation=true`. Crucially, `MeshValidator.h` (~145–154) runs the projection-dependent `quad_self_intersects` **unconditionally**, even for `topologyOnly`; the only tests suppressed by `topologyOnly` are the separate quadratic global face-to-face scan and geometric T-junction scan (~219–225). This means the first `SelfIntersectingFace` can precede the interior directed-edge `FlippedFace` census in the same validation call. **The global source-authoritative scan is not the `MeshValidator.h` quadratic scan**: `SourceAuthoritativeMeshValidator.cpp` (~1302–1351) builds an AABB tree over fan-triangulated output faces, then reports a separate `SelfIntersectingFace`. The existing issue fields already disambiguate origins: local projected-face issues carry `edgeFirst=edgeSecond=-1` and the quad index in `face`; global BVH issues carry the intersecting face indices in `edgeFirst` and `edgeSecond`. An added enum/counter is not necessary for this forensic split. Historic RA-201 scratch observed 249 local and one global instance; it does not measure the post-CB92 Vase case.

## Independent two-quad winding counterexample (new in this continuation)

A minimal **two-quad**, integer-coordinate construction proves that `orient_quads_to_source_normals` can create an invalid shared-edge direction from consistently oriented input, even when both quads have the same +Z source normal. Numbered vertices are `0=(0,0), 1=(1,0), 2=(2,-1), 3=(0,10), 4=(0,-2), 5=(1,-2)`. Initial quads are `Q0=(0,1,2,3)` and `Q1=(1,0,4,5)`. Their complete shoelace signed double-areas are **+19 and +4**, and they traverse shared edge `(0,1)` in **opposite** directions (`0→1` and `1→0`). Their first-triangle signed crosses are **−1 and +2** respectively. The per-face helper flips only `Q0` to `(0,3,2,1)`. Final complete polygon signed double-areas become **−19 and +4**; the shared edge is traversed `1→0` by **both** faces, triggering `FlippedFace` in the source-authoritative validator.

The results were independently computed in exact integer arithmetic, without building or running Directional; the standalone reproducer is `orientation_independent_witness.py` (downloadable with this Review). A separate polygon intersection check reported zero overlap area between the original two planar face interiors, but that supplementary check is not essential to the winding proof. This is **general root-cause evidence** for the helper; no observed post-CB92 Vase face or shared edge has yet been linked to it. It must not be credited as Vase regression repair or runtime acceptance.

## Completion-to-validator rejection without any flip (additional independent witness)

A second integer-coordinate witness isolates a **distinct** projection mismatch even when `orient_quads_to_source_normals` leaves a quad unchanged. Ordered corners are `A=(2,4,-5)`, `B=(-1,6,-3)`, `C=(7,-4,7)`, `D=(0,-3,-7)`. Treat `(A,B,C)` and `(A,C,D)` as adjacent source triangles sharing the same diagonal with opposite traversal; their oriented normals are `T0=(40,46,14)` and `T1=(100,-14,-51)` (`T0·T1=2642 > 0`). The quad's full Newell normal equals `T0+T1=(140,32,-37)`. Its two opposed 3D edge pairs are skew (nonzero exact scalar triple products `+430` and `−430`), so they do **not** intersect as physical line segments.

- `PureQuadCompletion.cpp:500–579` projects along the Newell dominant component **X**, obtaining YZ opposite-edge strict-intersection = **false**; with corner provenance on the two source triangles (`0,0,1,1`), its unit-normal source sum has alignment cosine **0.98161027**, above the 60-degree threshold, so the local completion embedding predicate **passes**. The constructed quad has distinct vertices, nonzero projected signed area, and a one-quad disc topology.
- `RemeshPipeline.cpp:10949–11033` sees the first-triangle normal `T0`, whose dot product is positive with **either** source-triangle normal. Hence the intermediate helper **does not flip** this quad no matter which of those two source triangles the centroid fallback selects.
- `MeshValidator.h:307–325` instead uses the first-triangle dominant component **Y**, obtaining XZ strict opposite-edge intersection = **true** on the **same ordered geometry**, so `validate_surface_mesh(...topologyOnly=true)` appends `SelfIntersectingFace` (the test is unconditional at ~145–154). This occurs before the source-authoritative global BVH scan and does not depend on a shared-edge winding conflict.

Standalone exact-integer assertions plus the source-normal floating alignment computation are in the downloadable `p13l_projection_disagreement_witness.py`; output included `STATUS=COMPLETE`. **Scope:** this establishes that passing the local completion embedding predicate is insufficient to pass the output validator, and that a projected bow-tie label need not correspond to intersection of 3D opposite edges. It does not establish that the full constructed input would pass all SourceCells authority/rail conditions, that a nonplanar quad should meet every production-quality condition, or that any specific Vase quad exhibits this disagreement. Nothing here authorizes weakening either validation gate. Source and predicate reconciliation needs an independently defined nonplanar surface-chart embedding requirement, not simply adoption of whichever projection accepts more faces.

## Causal alternatives still open

- **A — Pre-existing invalid winding:** patch local cycles or assembly produce same-direction interior edges before the normal helper; the helper may leave them or alter the set. Correct at the earliest patch/assembly ownership stage using shared-edge direction and source-chart authority, not a post-hoc geometric flip.
- **B — Introduced invalid winding:** input cycles are consistently oriented but the per-face helper creates new same-direction edges by inconsistent independent flips. Correct the orientation procedure with an authoritative whole-polygon source test and a globally coherent face-orientation propagation constrained by source sheets/rails; never merely force all faces to one normal.
- **C — Both:** an already-inconsistent assembly becomes more inconsistent after independent flips. Address both at their respective producers.
- **D — Genuine invalid embedding:** an independent geometric predicate confirms crossing, overlap, or fold in the same corner/vertex geometry before and after the helper. Correct the earliest patch/completion placement or stitch producer; do not relax validation.
- **E — Projection-induced false classification:** the local validator changes its crossing label because the helper changes the projected axis, while independent 3D/source-chart geometry remains valid. Correct the projection/embedding predicate and keep truly invalid cases rejected.
- **F — Completion/output predicate disagreement without a flip:** the same ordered quad passes the local Newell-based embedding gate but fails the downstream first-triangle-projected local self-intersection predicate. Independently reconcile surface-chart validity before assigning a producer; the additional witness proves this mechanism can occur without a changed corner order.

The independent two-quad witness proves the B mechanism is possible, but does not prove it occurred in Vase. Current immutable TB82 logs do not publish the required side-by-side mesh or per-face lineage; therefore **none of A–F can yet be declared the actual Vase cause**. The specific helper defect and missing directed assembler gate are proven from source, but their quantitative contribution remains unmeasured.
