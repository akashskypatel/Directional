## Proven source-level orientation defect

1. `src/pipeline/RemeshPipeline.cpp`, `orient_quads_to_source_normals` (~10949–11033): treats each quad separately. It computes the normal as `(B-A) × (C-A)` using **only the first three corners**, and swaps corners 1 and 3 if it disagrees with a selected source normal. This does not preserve relative orientation on shared interior edges. The function accepts but ignores `quadLineage`, uses a common face only when all four corner provenance records name the identical source-face row, and otherwise queries an unrestricted centroid projection. Projection is not the same as authoritative compatible source-chart provenance, especially for close sheets.
2. This three-corner normal is not a valid general substitute for whole-quad signed orientation. Exact planar counterexample with ordered corners `A=(0,0)`, `B=(1,0)`, `C=(2,-1)`, `D=(0,10)` and +Z source normal: the polygon is simple, full signed double-area is **+19**, but the first-triangle signed cross is **−1**. The helper reverses it to `(A,D,C,B)`, changing full signed double-area to **−19**. This demonstrates a **possible incorrect flip** without invoking the production binary. It does not prove these four points occur in Vase; the example is an algebraic falsifier of the helper's claimed general orientation predicate.
3. `src/geometry/PureQuadCompletion.cpp`, `quad_embedding_failure` (~500–579), already computes a complete Newell polygon normal and compares it to source orientation (60-degree agreement threshold), rather than using the first triangle. Therefore completion and the later pipeline normal-repair step use **inconsistent geometric predicates**.
4. `src/geometry/PureQuadCompletion.cpp`, `stitch_pure_quad_patches` (~3744–3950): publishes the completed-face corner cycles as-is. Its initial `edge_incidence` gate checks only unoriented edge multiplicities 1 or 2; it has no directed opposite-twin check. It validates Euler, vertex-fan connectivity, component and boundary loops, but these checks can all pass with same-direction shared-edge traversal. This is an **upstream diagnostic gap**. The absence of a guard does not prove the assembler is the original Vase orientation producer.
5. `src/pipeline/RemeshPipeline.cpp` (~14407–14473, 14847, 15008–15040): converts stitched quads to `completedQuads`, runs the independent per-face normal helper, then invokes `validate_source_authoritative_final_surface_mesh` **before optimization**. When this returns unaccepted it attributes failure to `completion/output-validation` and exits before the optimizer. It is a pre-optimization validation boundary, not proof that the completion topology producer itself is responsible for the failing predicate.

## Additional validator defect: the failure label is winding-dependent

`include/directional/validation/MeshValidator.h`, `quad_self_intersects` (~307–325), selects a projection axis from the first triangle `(p1-p0)×(p2-p0)` before checking opposite-edge crossings. Reversing the same cycle (`0,1,2,3` → `0,3,2,1`) can change that chosen axis. Therefore a `SelfIntersectingFace` issue may change even when all physical corner positions and undirected edges are unchanged. This is a **source-proven diagnostic instability**, distinct from the actual geometric shape and from the orientation helper's wrong-normal defect.

Independent integer-arithmetic witness: `A=(0,0,0)`, `B=(3,1,0)`, `C=(2,2,1)`, `D=(-4,-3,-3)`. The forward `(A,B,C,D)` first-triangle normal is `(1,-3,4)`, so the validator projects to XY (drop Z) and reports **no strict opposite-edge crossing**. Reversal `(A,D,C,B)` has first-triangle normal `(3,-2,-2)`, so it projects to YZ (drop X) and reports **a strict crossing**. The four points and undirected polygon edges are identical. This is a deterministic counterexample to orientation-invariance of that *validator*, not evidence that Vase has these coordinates or that its geometric embedding is valid. A projection-independent source-chart/bilinear or true 3D edge/face oracle is required before interpreting the post-orientation intersection count.

The global face-to-face scanner uses fan triangulations anchored at vertex 0 (`MeshValidator.h` ~414–445), and its `SelfIntersectingFace` label is shared with the local quad check. A count under that label must therefore also be split by **local projected-edge check versus global nonadjacent-face collision**. Do not equate the shared enum with one physical cause.

## Causal alternatives still open

- **A — Pre-existing invalid winding:** patch local cycles or assembly produce same-direction interior edges before the normal helper; the helper may leave them or alter the set. Correct at the earliest patch/assembly ownership stage using shared-edge direction and source-chart authority, not a post-hoc geometric flip.
- **B — Introduced invalid winding:** input cycles are consistently oriented but the per-face helper creates new same-direction edges by inconsistent independent flips. Correct the orientation procedure with an authoritative whole-polygon source test and a globally coherent face-orientation propagation constrained by source sheets/rails; never merely force all faces to one normal.
- **C — Both:** an already-inconsistent assembly becomes more inconsistent after independent flips. Address both at their respective producers.
- **D — Genuine invalid embedding:** an independent geometric predicate confirms crossing, overlap, or fold in the same corner/vertex geometry before and after the helper. Correct the earliest patch/completion placement or stitch producer; do not relax validation.
- **E — Projection-induced false classification:** the local validator changes its crossing label because the helper changes the projected axis, while independent 3D/source-chart geometry remains valid. Correct the projection/embedding predicate and keep truly invalid cases rejected.

Current immutable TB82 logs do not publish the required side-by-side mesh or per-face lineage; therefore **none of A–E can yet be declared the actual Vase cause**. The specific helper defect and missing directed assembler gate are proven from source, but their quantitative contribution remains unmeasured.
