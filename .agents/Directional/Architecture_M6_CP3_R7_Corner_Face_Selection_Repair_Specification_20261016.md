## Determination

**The required raw witness producers exist for a *bounded planar, directed-side repair*, but one node-wide `SurfaceTracePoint::face` cannot serve as the authoritative face of every side meeting that node.** The repair must bind a directed *side endpoint occurrence* to its already-produced oriented boundary path, retaining a separate canonical geometric lattice-node identity. The existing source artifacts do **not** themselves prove that every conceivable path is globally unique or A3-compatible; the future implementation must enforce these predicates and fail closed when they are false. No new vertex-star certificate is licensed and no late A4 admission bypass is permitted.

The proposed alternative, sorting `activeFaces` or selecting a different single face for each node, is **rejected as a general repair**. A face-identity check added alone to `validate_closed_boundary_paths` is only a **rejection relocation**, not a repair.

**RA-65.5 verdict:** No missing upstream producer is required merely to *obtain* side-associated face/barycentric evidence in the planar producer: `segment_on_source` already produces it before the edges are minted. In contrast, the **verification and propagation of that evidence as authoritative side-occurrence endpoints is not implemented**. A redesign of A4 vertex-star admission, an unproved path-uniqueness assumption, or an invented corner-sector certificate would still fail the producer test. This is an admissible *bounded implementation specification*, **not** a proof of corrected output or authorization to implement before independent Review.

**Limit on determinism:** `segment_on_source` chooses the smallest `interval.face` whose interval covers a nonzero midpoint (`:12086-12117`). This is an independently order-sensitive *path-face* tie-break on overlapping source support, not a semantic certificate. Future binding must preserve the emitted path's actual source and topology authority and separately verify face-row/triangulation permutations; do not assert that the existing midpoint choice is invariant or try to repair it by changing `point_on_source` tolerance.

### 2. Per-node versus per-directed-side — structural necessity

`point_on_source` chooses one `face` for each `(u,v)` node (`:12949-12958`) before any boundary segment exists. `cell.corners[corner]` copies that choice (`:12986-12987`) and `SurfaceFrontEdge.from/to` copy the corners (`:13033-13035`). In contrast, each directed boundary path is constructed independently (`:13012-13021`) and may approach a shared node from a different incident source triangle. One node can be part of as many as four adjacent cells; each cell has an incoming and outgoing oriented side incidence. Those incidences are not one source-face occurrence.

For a concrete source-static counterexample, the component-local 3×3 planar feature fixture has vertex 4 shared by source faces `{0,1,3,4,6,7}` and two hard edges `(1,4)` / `(4,7)` (`tests/SurfaceCellsPhase10Tests.cpp:223-273`). Every one of these triangles contains the vertex exactly, hence the `point_on_source` test admits all six and returns the first face in `activeFaces`. In the measured RA-70 TB5 junction population (**21/44**), a corner endpoint has `toFace=7` while its owning second traced path has face `{3}` and the original retained carrier `(1,4)` has incident faces `{0,3}`. The **23/44** interior-shaped controls have `toFace=3`, second path `{3}`. The two families share the first traced face `{0}`. These are measurements of this one semantic baseline, not a new run and not a guarantee that changing a face will make them GREEN.

Even if changing the node's first-match order yielded face 3 for that particular endpoint, any incident side using a different source sector would still require its own occurrence face. A per-node fix can only work under a *proved* special condition that **every** incident directed path agrees on a single admissible face compatible with the selected carrier and chart. The general repair is therefore **per-directed-side endpoint binding** (or an equivalent explicit, source-attested reconciliation mapping), not a universal per-node face.

The geometric corner remains one lattice node for cell geometry, adjacency, shared coordinates, and topology. It may need multiple `SurfaceTracePoint` representations associated with side occurrences. A source vertex encoded as `(face 7,bary=(...,1,...))` and in face 3 at the *same* source vertex can be topologically the same node while **not** being interchangeable as an A4 oriented carrier-face witness. Neither worldwide position nor integer face-row equality is the underlying identity rule; compare canonical source-vertex/source-edge occurrence and the selected directed side's source-route provenance.

### 3. Proposed minimum repair contract (for a separately authorized Code + Build turn)

1. **Keep the existing producers.** Build lattice nodes, all four oriented side paths, source topology and A3 metadata as now. Do not replace `segment_on_source`, retune `1.0e-10`, add global phase integration, or alter fallback/annulus/curved producers as part of this narrow first repair.
2. **Bind each directed side's endpoint representation from its own path.** The start is `path.front().face/startBarycentric`; the end is `path.back().face/endBarycentric`. Retain the node's canonical geometric identity separately. Accept each representation only after a source-entity correspondence, canonical region/sheet constraint, A3 chart/branch transport and path/rail incidence check tied to the owner side. A face at the same XYZ point is insufficient.
3. **Reconcile both cell-corner incidences.** At a cell corner, incoming side end and outgoing side start may use distinct faces. Preserve a single 3D/quadrilateral corner and phase lattice coordinate, but never force both side endpoint witnesses to share one `face`. If exact intrinsic identity, chart or transport cannot be certified, reject with a typed producer-stage failure; do not take first match or bypass A4.
4. **Update all dependent endpoint state transactionally.** Reconcile `SurfaceFrontEdge.from/to` with their actual path endpoints; update face-derived `fromLattice/toLattice` source chart and branch rotations while preserving lattice coordinate, phase, family/sign, region, sheet, and signed transport. Validate reciprocal paired edges, boundaries, hard rails, and periodic relations before publishing the phase-front product. `reverse_phase_front_cell_cycle` (`:12431-12444`) must reverse the side-occurrence bindings with their paths, not swap an unrelated node face into the endpoint.
5. **Retain hard downstream gates.** A2b exact ordinals, `SurfaceHardRailFieldTransition` edge/face/quarter-turn admission, A3 typed routes, `endpoint_certificate`, whole-rail terminal restrictions, arrangement provenance and fail-closed source-authoritative validation remain mandatory. No source-face waiver at A4 or whole-rail splice inferred from the 21 rejected samples.

**Minimum affected source interfaces (to audit before implementation):** `point_on_source`/node sampling (`:11477-11509`, `:12949-12958`); `SurfacePhaseFrontCell::{corners,lattice,boundaryPaths}` and `SurfaceFrontEdge::{from,to,fromLattice,toLattice}` (`SurfaceCellTracing.h:1713-1722,1545-1579`); path production (`:12050+`, `:13012-13021`); cycle reversal and validator (`:12431-12444`, `:12718`, `:12736`, `:7319-7357`); edge construction/pairing and rail route authority (`:13030-13143`, `:12481-12692`); publication and A4 consumption (`:19781-19803`, `:19353-19360`). Source-row ordering and other phase-front producers (`:14774`, `:17345`) are controls, **not** casually in-scope writers to rewrite. Guard all later uses of `cell.corners` and face-derived lattice/chart fields, not only the displayed rejection site.

### 4. Rejection relocation is not repair

A direct literal `corner.face == boundaryPaths[side].front().face` / corresponding last-face requirement inside `validate_closed_boundary_paths` (`:7319-7357`; called at `:12718` and `:12736`) would catch the measured face 7 vs face 3 discrepancy *earlier* and cause a producer-stage closure rejection. Such a check by itself would **not** produce a usable cell, would not change a route's face incidence, would not resolve different incoming/outgoing face occurrences at one node, and would not make `RP-01` green. It would also overreject legitimate adjacent-face representations of a canonical source vertex or edge if imposed globally without source-entity equivalence. Therefore a strict face-identity check is at most a targeted diagnostic/guard **after** the side-specific authority contract is defined; it is not the proposed fix and cannot be counted as recovery or acceptance.

### 5. Independent falsifiers and follow-on evidence boundary

The independent Review should reject or narrow this proposal if **any** of the following holds in actual source: (F1) a measured rejected edge does not derive from the planar producer and the stated path, (F2) its `SurfaceTraceSegment` endpoint does not encode the reported owning face/vertex in source barycentrics, (F3) a first/last segment's actual carrier is incompatible with the peer/edge route despite a nominal matching face, (F4) the selected endpoint cannot be proved to lie on the **same canonical source entity** as the lattice node without crossing region/sheet or hard rail, (F5) the two sides of a paired edge cannot be consistently rebound while keeping their exact topology and A3 transport, (F6) a downstream consumer implicitly assumes `cell.corners[*].face` and every side occurrence are identical, (F7) a second admissible path or unresolved row-order ambiguity makes purported repair witness non-unique. State which falsifier fails and the precise missing upstream witness rather than selecting a synthetic face or accepting a late A4 exception.

Only a separately authorized artifact-only Test + Benchmark turn may measure the 21 junction identities, 23 controls, face-row permutations, reverse cycles, close-sheet/region barriers, genuine hard-rail endpoints, paired front edge ownership and full final acceptance. No tests/benchmarks were executed in this Definition turn.
