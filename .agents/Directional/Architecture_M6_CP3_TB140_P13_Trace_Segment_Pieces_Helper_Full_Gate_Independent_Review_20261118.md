### S1 — ruling on the static falsifiers

1. **Upheld: the plan validator.** `GlobalTopologyPlan.cpp:2689–2705` requires `sourcePath.size() == sourceFaces.size()` and a `SourceFaceInteriorSupport` piece on `sourceFaces[i]` at each index. Production reaches it (`RemeshPipeline.cpp:12958` → `make` → `make_from_candidate` → `validate_candidate_structure`). Any mixed path fails `InvalidSourceBinding`. This alone makes an EmbeddedGraphTopology-only CB166 unsound.
2. **Partly rejected: region construction and the cut graph.** Neither reads `sourcePath`. They are traversal-level (combinatorial) certifiers keyed by segment: region counts one chord per non-excluded segment (`:1279`, expected = count + 1, only excess rejected `:1464`), applies the third-edge rule to the nominal carriers (`:1320–1350`), and labels fragments with dart orbits. The cut graph inserts the **whole** incoming and outgoing carrier of every segment into `barriers` (`SurfaceCutGraph.cpp:566–570`). The component partition never unions across a barrier (`SourceFaceComponentPartition.h:70`). Whole-edge occupancy is the existing rule for an ordinary crossing too, so it is not a slide defect. For a **grazing** segment F=(a,b,c), entry on ab, slide on ac from s to c, the real path entry→s→c is homotopic in closed F to the old chord entry→c. The fragments still number two, bc is on the same side and ac is touched, so every traversal-level fact is unchanged. Partial edge intervals in the cut graph are therefore a new feature, not an H4 requirement, and are rejected for this scope. Exact geometry is already certified by `actual_complement_component_count` (`EmbeddedGraphTopology.cpp:3097–3125`), which already turns `SourceEdgeSupport` pieces into barrier intervals.
3. **Upheld, but separate: edge-only segments (departure/vertex slide).** Region and cut graph count an edge-only segment as a chord of F, insert F into `traceCutFaces` and give F both orbits, one of which lies across the carrier. This is wrong today, with or without H4 (the old chord v→w lies on the edge). Once the cutover publishes an edge piece, the exact complement count and the region count will disagree. Recorded as **O49**. It is in scope only when an edge-only slide reaches a published graph; see S3.
4. **New gap: no evidence that any slide is published.** `slideProposal` (CB164) is printed before commit (`SurfaceCellTracing.cpp:3770`; commit `:4079`). Proposals can be discarded (`:4305–4307`, `:4540`), and a contact commit keeps a slide the trace never traverses (`:4113`, `:4133`). No receipt reports kept slides, and no test publishes a slide through graph, cut graph or plan. The 1,200 gate proposals do not show a published slide. RA-261 S1 "H4 is live" holds for proposals only; for publication it is **unmeasured**. CB166 measures it.

### S2 — the contract (EPO), approved

- **EPO-1, two layers.** *Traversal layer:* `sourceFaces` (one per segment, ordered traversal identity), the segment range, nominal carriers, region fragment counts, owners and the third-edge rule, whole-edge cut-graph barriers and `traceCutFaces`. It is restructured as a single-segment leaf that never calls `exact_trace_path`; `exact_trace_path` and `exact_trace_path_between` only concatenate leaf output. - **EPO-3, explicit binding.** `GlobalTopologyArc` and `ArcDraft` gain `sourcePieceCounts`, parallel to `sourceFaces`, with each count in {1,2}. The canonical-path check and the exact replay (`:2944`) both stay. No piece mapping is inferred from geometry.

- **EPO-5, unchanged.** Interior cuts on a slide stay fail-closed. A contact before the slide publishes only the clipped face piece. No partial barriers. Ordinary segments are byte-identical.
- **EPO-6, edge-only segments.** Before an edge-only segment is published as an edge piece, the traversal layer must give it zero chords, leave F out of `traceCutFaces`, and give the forward orbit to F and the reverse orbit to the face across the carrier (O49). That is allowed only if CB166 shows no traversed edge-only slide in any fixture that reaches graph build.
