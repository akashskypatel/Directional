## Decisive distinction: source pieces are not output intervals

- CB110 already produces canonical oriented chains and exact concatenated support (`GlobalConformityBaselineSupport.cpp:414–520`). D7b already locates a scheduled breakpoint on **any** support piece, with an exact piece-local fraction (`:302–369`). These are reusable; no new metric or chain-ID type is needed.
- A span with three source pieces and final scheduled count **1** has one logical output front interval `[0,1]` whose source route walks all three pieces. Internal source vertices are trace/path support, not automatically output quad corners. Count 2 gives two global unit intervals `[0,1]`, `[1,2]`, potentially each crossing a source-piece boundary.
- Therefore the final `SurfaceSharedBoundaryInterval` unit-width checks **must not be relaxed**. The earlier working record's suggestion of fractional *final* ordinal width is **superseded**. Only piece-local position may be fractional. The source itself represents both exact-rational breakpoint positions and exact-rational interval endpoints, but representation alone does not authorize different front topology.
- The current curved-disk producer instead iterates raw source edges and then all schedule ordinals, yielding a front interval per edge per count (`SurfaceCellTracing.cpp:17421–17724`). That algorithm must be replaced with global consecutive-breakpoint traversal whose single logical edge may have multi-piece source support. The four accepted rectangular boundary sides are then subdivided by **output** count, not source-piece count.
- A source-independent `fractions.Fraction` scratch example for equal collinear three-piece spans gave 1/2/3/4 logical intervals for scheduled counts 1/2/3/4, with correct piece coverage, but did **not** execute Directional, prove weighted-run placement or prove curved-disk chart validity.
