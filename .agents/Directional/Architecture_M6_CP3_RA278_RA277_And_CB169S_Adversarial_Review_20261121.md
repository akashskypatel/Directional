But it contains four code defects that would stop or mislead its first Test + Benchmark turn: a digest change that breaks the census, a replaced ordinary edge-locus rank, silent along-edge tie-breaks, and a weakened accepted assertion. ## Assessment

### A1 — RA-277 gaps (design, not procedure)

1. It re-authorized a five-concern successor with no exact diff and no changed-row list, so the following TB had no decidable comparison rule.
2. It carried "count hash" as an obligation without checking RA-273 S2.3's reason: Cylinder builds a plan and its census `platform-digest` prints that plan's digest (`RemeshPipeline.cpp:13006–13008`). See A2.1.
3. It accepted "update the chord test premise" without measuring whether the premise's fixture has slides. See A2.4.
4. It carried the TB154 Review's restatement of RA-275 S4 ("opposite winding sides via `edge_piece_face_side`"). RA-275 S4 actually asks for (a) a per-fixture check that an uncut component bordering only a published slide keeps its seed, and (b) a grep of accepted tests for `notTraceCutReason` names. (b) is answered here: no accepted test pins a value. `region_frontier_interior_arc_census_is_valid` (`tests/FieldAlignedCurveNetworkTests.cpp:5506`) accepts the closed name set, and `UncutComponentArcIncidenceCensusPublishesOnOwnershipFailure` checks only `!= "Unknown"`. (a) stays with TB-REV-155.
5. RA-277-NV1 is valid, and CB169S's row 971 strengthening answers it (ten expected carriers and vertices, along-edge type, full coverage, collisions, ordinary-ray preservation).

### A2 — CB169S code review (`ee0f478ad`)

1. **C1 — the digest change breaks the census and adds no identity.** `candidate_semantic_digest` now hashes `sourcePieceCounts.size()` and each count for every arc, including an extra zero for every mandatory and cut arc. Every plan digest changes, so Cylinder's census `platform-digest` (and the conformity-baseline and tracing digests that embed it, `GlobalConformityBaseline.cpp:255`, `RemeshPipeline.cpp:2094`) cannot MATCH TB151. The field is also redundant. The digest is computed only after `validate_candidate_structure` passes (`GlobalTopologyPlan.cpp:3047–3055`), and that function's exact replay rejects `candidate.arcs != wanted.arcs` (`:2946`) under `GlobalTopologyArc`'s defaulted `operator<=>`, which includes `sourcePieceCounts` (`GlobalTopologyPlan.h:61–63`). Every digested plan's counts are therefore the network-owned rebuild's, whose inputs, faces, segment range and path are already hashed. No test can make two valid plans differ only in counts. **RA-273 S2.3's "counts enter the digest at the cutover" is withdrawn; revert (CB-170).**
2. **C2 — the ordinary edge-locus rank was replaced.** At both edge-locus call sites, the legacy carrier-based `edge_locus_secondary_rank` was replaced for *every* trace ray by a new `edge_piece_into_face_rank`. That rank returns no rank when the far end is a face point (a terminal face contact or an interior cut), where the legacy rank succeeded, so arcs from an edge locus to a face contact would newly fail the rotation system. This violates EPO-5 (ordinary rays unchanged). For an into-face piece at an edge locus, the legacy rank already points toward the carrier that the face piece ends on (the slide's face piece ends on `outgoingCarrier`), so restoring it loses nothing. **Restore it, with its original primaries, for into-face rays (CB-171).**
3. **C3 — silent tie-breaks.** A vertex along-edge trace ray gets `primary = 2·edgeSlot`, `secondary = 0`, the same key as a mandatory or cut arc on that edge. At an edge locus an along-locus-edge trace gets primary 0/2, the same as the locus edge's own edge-arc halves. The post-sort collision check covers only trace/trace pairs at vertex loci, so these coincidences are ordered by `RayOrderKey`'s kind/arc-id fields, a new tie-break that EPO-4 forbids. The sphere has none (`coincidentWithEdgeArc=0`, `alongLocusEdge=0`). **Fail closed with a typed reason (CB-171).** The edge-locus along-edge ordering itself (0 toward the second endpoint, sides at `2·side+1`, 2 toward the first endpoint) is geometrically consistent, but no fixture witnesses it. It also renumbered the into-face primaries of every edge locus without edge arcs from `side` to `2·side+1`. That keeps the order but changes the `primary=` values the rotation-failure diagnostics print (tests print them, including the census acceptance test). **The untested rule is withdrawn:** an along-locus-edge trace ray fails closed with a typed reason, and into-face primaries and diagnostics return to their exact pre-CB169S form. Ordering is defined when a fixture witnesses an edge-locus slide end.
4. **C4 — weakened accepted assertion.** Row 966 (`IndependentValidationBindsTraceSegmentsToSourcePieceCounts`, real-tracer `build_cp3b_event_fixture`) replaced the exact `counts == ones` with size/sum/binding checks. The validator already enforces those for any plan that builds, so the test no longer detects a producer that emits two pieces for a segment without edge transit. **Restore exactness from an independent record: a segment with neither `edgeTransitEntry` nor `edgeTransitExit` must have count 1; publish transit segments (CB-170).**
5. **Accepted as written:** `build_arcs` publishes `exact_trace_piece_path_between` with counts and the binding check, and leaves mandatory/cut arcs unchanged. Vertex rays read the arc's own first piece through `vertex_piece_ray`, in-wedge parameters are taken from that piece, and along-edge rays get the edge slot. The row 971 strengthening is also accepted.
6. **Observations, not corrected:** (a) vertex piece-ray failures all report `SecondPointUnavailable`, losing the typed sub-reason; (b) `vertex_locus_secondary_parameter` now has no production caller, so rows 665/666 test a legacy oracle, not production rays, and production vertex-ray coverage is rows 969–971 plus the gate; (c) the legacy edge rank still approximates a ray toward an interior face point by its carrier, a pre-existing limit made explicit here.

## Lessons

- Switch only the branch the new representation creates. Replacing a whole reader (the edge-locus rank) changes ordinary configurations that the representation left unchanged.
- A new key that shares a slot with an existing key kind (an along-edge trace ray beside an edge arc) needs an explicit coincidence check. Falling through to a sort on id fields is a hidden tie-break.
- A structural check that the validator already enforces is weaker than the exact assertion it replaced. Restore exactness from an independent record.
- Before adding a field to a semantic digest, check whether an exact replay already pins it. A defaulted `operator<=>` over the record means it does.
