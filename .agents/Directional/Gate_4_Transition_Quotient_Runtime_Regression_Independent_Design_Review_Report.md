## Review question 1 - boundary topology versus transition index

Approved representation:

- `sourceRouteTopology` is the canonical source-edge identity for a source-supported side.
- `sourceRouteEdges` stores interior transition/matching indices; it is not a universal source-edge identifier.
- A `GenuineSourceBoundary` must have non-empty canonical topology, every key must have exactly one incident source face, and `sourceRouteEdges` must be empty.
- `HardRail`, `EmbeddedReliefCut`, and `PeriodicCut` are two-face routes and require one valid interior index per topology key, in the same order.
- Ordinary cross-face transport continues to require `transitionSourceEdges` for every crossed edge. An empty transition route is valid only when no cross-face transport occurred.
- Do not add boundary edges to `edge_matching_indices()` and do not invent sentinel indices. Either would conflate domains or destabilize the established interior indexing.

Required counterfactuals cover genuine boundary, ordinary interior, hard rail, embedded relief, and periodic cut behavior.

## Review question 2 - exact isolation-seam consumption

Approved model: **reciprocal seam-transport certificate consumed as local-sheet connectivity authority**.

For every `SurfaceTopologyRegion::internalIsolationSeamTopology` entry, the producer must emit exactly one canonical certificate containing:

- source component and topology-region owner;
- canonical source-edge topology and its valid two-face interior source-edge index;
- both canonical incident source-face identities and both local-isolation labels;
- forward and reverse field-transition/quarter-turn authority proving reciprocity.

The certificate is created only after exact source adjacency and reciprocal transport validation. Its canonical identity must be independent of face-row and discovery order.

The materializer must:

1. require a one-to-one match between retained seam topology and certificates;
2. revalidate source incidence, region/component ownership, distinct local sheets, interior index, canonical ordering, and reciprocal inverse transport;
3. build each region's permitted local-sheet connectivity graph from the validated certificates;
4. require every multi-sheet cell, front, periodic relation, quotient class, and retained lineage set to be connected by that graph;
5. require any explicit cell-side seam crossing or cross-sheet ordinary equivalence to reference a matching certificate and retain its topology in equivalence/lineage provenance;
6. count a seam as consumed only after the certificate participates in this materializer validation, and hash/diagnose all certificate fields.

This uses every seam as transport authority without asserting that every source seam edge must be intersected by an output side. A certificate that is merely present, duplicated, missing, nonreciprocal, assigned to the wrong region/sheets, or disconnected from the consumed region fails closed.

Rejected alternatives:

- unconditional `consumed = required` assignment;
- deleting the seam-consumption invariant;
- retaining topology keys without reciprocal transport data;
- requiring every seam to occur in `transitionSourceEdges`;
- representative-sheet selection;
- lattice/position coincidence;
- count, ID, row order, frequency, boundary length, or proximity selection.
