## 1. Previously omitted producer input: feature-curve corners

- `include/directional/geometry/AdaptiveFeatureMap.h:91–117` publishes `AdaptiveFeatureCurve {id,component,edges,vertices,closed,corners,junctions}`, with `AdaptiveFeatureMap::edges/curves`. The feature builder identifies degree-two geometric corners via the configured `cornerAngleDegrees` (`:55, 650–658, 765–807`) and curve junctions by feature-edge degree. These are *not* interchangeable with every ordinary source-triangulation vertex.
- `src/pipeline/RemeshPipeline.cpp:12548–12565` builds and retains `featureMap` from `meshWhole.V, meshWhole.F` and **the effective selected feature options** (`options.featureAlign ? options.featureMap : options.surfaceCells.featureMap`). `result.surfaceCellContext.featureMap` is a one-way observation copy; a producer must use local stage authority.
- `src/pipeline/RemeshPipeline.cpp:9730–9785, 9810–9905` constructs `SurfaceCellRail` runs from each curve using edge classification and source topology. A rail run may span a feature-curve **corner**: `emit_run` appends all run intervals and does not split the run solely at `curve.corners`. Thus `same HardRailId` and exactly two Mandatory incidences at the join **do not certify that the join is unprotected**.
- `SurfaceCellRail {id,kind,curveId,component,closed,sourceVertices,sourceEdges}` (`SurfaceCellTracing.h:107–116`) carries `curveId`, but **does not carry the curve corner or junction set**. The previous proposed product inputs (`meshWhole.F`, A2b, network, source regions, rails) omit this independently available protection predicate. A new chain builder or validator which only checks the rail/node/region inputs could join across a protected corner without noticing.

**Required narrow input correction:** pass the existing stage-local `featureMap` **and** its selected `AdaptiveFeatureMapOptions`, plus `meshWhole.V` (alongside already required oriented `meshWhole.F`), into chain candidate construction and the independent verifier. Do not infer corners from A2b arc IDs, `HardRailId` equality, exact endpoint matching or source-face row order. Do not add a duplicate source-vertex/feature-curve graph merely to carry this information; use the existing feature-curve and rail references.

## 2. Exact join veto and independent proof

At a candidate join `v` between successive original Mandatory arcs:

1. Resolve each distinct `NetworkEdgeId` through `FieldAlignedCurveNetwork::mandatory_edges()`, then resolve its `HardRailId` and source topology edge. The two source edges must be consecutive in the **same** validated `rail.sourceEdges` and must meet at `v` in `rail.sourceVertices`, with coherent orientation. No positional welding. A2b siblings split at one Trace terminal fail the separate Trace veto.
2. Verify `rail.curveId` against its owning `featureMap.curves` entry when present (the curve's **id**, not vector position alone); verify each ordered rail source edge is represented by that curve's source feature edges with matching kind/component. A standalone rail with `curveId == -1` has no cross-interval join because it contains one source edge.
3. A join is **ineligible** when `v` is a feature-map `curve.corners` or `curve.junctions` member, any other protected port/branch/Trace/Cut contact, a rail endpoint, or a feature/barrier-kind transition. A source vertex is **not** a barrier merely because the triangulation subdivides a straight rail.
4. Independent validator must derive the protected-corner decision from the stage `meshWhole.V`, curve edge membership, and the *selected* feature options, not simply trust a mutable `curve.corners` list or share the candidate builder's join helper. For degree-two members, reproduce the feature producer's corner-angle predicate including its absolute dot product; for junctions derive degree/membership. Reject incoherent/corrupted feature-map claims rather than silently treating a missing corner as unprotected.
5. All existing *other* predicates remain conjuncts: same component and side-specific sheet, same ordered A2b region/exterior occurrences, physically certified side/face incidence from oriented source faces, exact-support adjacency, unique rotation continuation, nonbranching rail, exclusion of uncut cycles and same-region loops. Correct feature protection alone does not prove admissibility.

**Two separately owned corner negatives (test-reachability correction):** (1) **candidate-only**: construct a separately certified two-network-edge run whose original feature curve has a designated protected corner at the shared source vertex. Hold the mesh, feature map/options, rail, network and A2b plan fixed and propose a joined chain using those existing original child IDs. The chain validator must independently rederive the protected corner and reject the candidate (not merely fail unrelated source preflight). The producer must keep separate units even when the authoritative rail remains one run. (2) **feature-authority integrity**: remove that corner **from a copied upstream `AdaptiveFeatureMap`**, keeping source vertices, feature edges and options fixed. This is not a mutable chain-candidate field. Its independent preflight must detect the inconsistent feature-map claim; attribute the rejection to the actual feature-input verifier, record whether the chain predicate was reached, and never count this as a separate candidate-only negative. A positive two-network-edge **straight unprotected** certified run must merge when all other join predicates pass; blanket singletons fail maximality and real Vase non-vacuity. If a fixture cannot reach its named validator, report `not exercised`.
