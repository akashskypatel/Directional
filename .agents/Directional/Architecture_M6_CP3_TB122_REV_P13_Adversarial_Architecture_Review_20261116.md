## Assessment — actionable findings in order

**C1 — HIGH: row 949 checks cross-face branch numbers without frame transport.** `tests/FieldAlignedCurveNetworkTests.cpp:12240–12328`, especially `:12326`, unconditionally compares `elected.nextBranch` and `follow.continuation.nextBranch`, including `cross`: top `(2,3,4)`, destination `(1,2,4)`. `FieldBranchTopology` contains face-specific branch pairings and `signedLift` adjacency maps (`include/directional/authority/FieldTransportAtlas.h:693–810`); `resolve_field_vertex_transit` uses `branch.rotated(directed->signedLift)` in `SurfaceCellTracing.cpp`, while follow selects the target sector branch. Raw equality is not a valid cross-face criterion. Actual row `949.log` gives elected 2 vs target 3; `Cross` and expected face did not fail. **What remains unproved:** target branch is the transported branch that also leaves the destination vertex in the correct wedge. A valid oracle must compute the expected branch independently from source geometry, A1 transitions and target-frame branch directions. It must not read the follow audit to construct expected output. Test alternate wrong destination branch, incorrect lift, direction pointing into vertex, and radial grazing; every invalid case must fail. A test-only change that merely deletes the equality is prohibited.

**C2 — HIGH: the owner and field-follow rules were not explicitly distinguished in DESIGN.** `DESIGN.md` Amendment 22 declares geodesic sector ownership independent of candidate field representatives. `SurfaceCellTracing.cpp:1913–2030` uses target **field** direction to move past the elected owner. D12=A is a legitimate later decision in RA-241, but no source of truth explained its post-election status or whether it may change the original owner certificate. This is a design-contract conflict, not proof that Cross is wrong. Normative clarification in DESIGN now freezes: owner is not re-elected; follow may produce a *separate* continuation or typed Unresolved; A1 branch transport, component/region barriers, rail constraints and exact radial tests remain binding. Do not relabel the target face as the original geodesic owner. Actual trace/event certificate retention remains unverified and requires a later focused evidence turn before P13-e outcome acceptance.

**C3 — HIGH: multiple mandatory-edge terminal cuts are not represented.** `src/geometry/EmbeddedGraphTopology.cpp:435–491` groups terminations by source edge and rejects any `cuts.size() >= 2`; `:494–558` creates exactly two mandatory sub-arcs for one terminal. This is a deliberate fail-closed construction limit, not evidence that every multi-terminal case is invalid. BunnyRandom first failed at `surface-cut-graph/CellularityNotEstablished/origin=MandatoryEdgeTerminalOrderUnresolved` on `(241,251)` after the new trace continuation; zero output and no accepted mesh. `SurfaceCellTracing.cpp:3895–3937` and `:4701–4736` publish contact nodes per barrier termination. Distinct exact cuts require N+1 positive sub-intervals, original mandatory owner, directed incidence, and invariant endpoint/trace binding.
